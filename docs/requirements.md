# terse-prompt 要件定義書

## 1. プロジェクト概要

### 1.1 目的
terse-promptは、端末制御ライブラリ「terse」をベースとして、Claude CodeのようなCLI REPLツールでユーザーからのテキスト入力を受け付けるための機能を提供するC言語ライブラリです。

### 1.2 位置づけ
- GNU readlineやlinenoiseに近い機能を持つが、特にCLI REPLツール向けに最適化
- 複数行のテキスト入力に対応
- 端末制御はterseに委譲し、編集機能の実装に集中

### 1.3 設計思想
- **シンプルな利用**: 1つの関数呼び出しで全機能が使えるラッパーを提供
- **高度なカスタマイズ**: カスタマイズ可能なフレームワークも提供
- **クロスプラットフォーム**: POSIX対応を基本とし、POSIX依存機能はソースファイルを分離

## 2. 機能要件

### 2.1 基本編集機能

#### 2.1.1 文字の入力と挿入（MUST）
- **ASCII文字の入力**: 全てのASCII文字を入力可能
- **UTF-8文字の入力**: 基本的な日本語（ひらがな、カタカナ、漢字）とASCIIに対応
- **カーソル位置への挿入**: カーソル位置に文字を挿入し、後続文字を右にシフト

#### 2.1.2 文字の削除（MUST）
- **Backspace**: カーソル左の文字を削除
- **Delete**: カーソル位置の文字を削除
- **行削除**: Ctrl+Uなどで行全体またはカーソルから行頭/行末までを削除

#### 2.1.3 カーソル移動（MUST）
Emacs風の操作体系を採用：

| 操作 | キーバインディング | 動作 |
|------|------------------|------|
| 左へ1文字移動 | ← / Ctrl+B | カーソルを左に1文字移動 |
| 右へ1文字移動 | → / Ctrl+F | カーソルを右に1文字移動 |
| 上へ1行移動 | ↑ / Ctrl+P | カーソルを上の物理行に移動 |
| 下へ1行移動 | ↓ / Ctrl+N | カーソルを下の物理行に移動 |
| 行頭/行末 | Home/End / Ctrl+A/E | 後述の段階的移動（2.2.3参照） |
| 単語単位移動 | Ctrl+← / Ctrl+→ | 単語の境界まで移動 |
| 文書先頭/末尾 | Ctrl+Home/End | 文書全体の先頭/末尾に移動 |

#### 2.1.4 入力確定（MUST）
- **Enterキー**: カーソル位置に関わらず、現在の入力内容を確定してライブラリ呼び出し元に返す

#### 2.1.5 将来課題（COULD）
- **コピー&ペースト**: 初期バージョンではOS機能のみ。ライブラリ内部のキルリング（Emacsスタイル）は将来実装
- **Undo/Redo**: 初期バージョンでは未実装。将来的に追加を検討

### 2.2 複数行編集

#### 2.2.1 論理行と物理行（MUST）
- **論理行**: ユーザーが入力したテキストの1行（Enterで区切られる）
- **物理行**: 端末幅に基づいて折り返された表示上の行

**例**: 端末幅80カラムで120カラムのテキストを入力した場合
```
論理行1: [────────80文字────────][──40文字──]
         ↓ 折り返し表示
物理行1: [────────80文字────────]
物理行2: [──40文字──]
```

#### 2.2.2 カーソル移動の動作（MUST）
- **上下矢印キー（Ctrl+N/P）**: 物理行間を移動
- **左右矢印キー（Ctrl+F/B）**: 文字単位で移動。物理行の境界をまたいで移動可能
  - 物理行1の末尾で→を押すと、物理行2の先頭に移動

#### 2.2.3 Home/Endキーの動作（MUST）
**Claude Codeスタイルの段階的移動**：

- **End / Ctrl+E**:
  1. 1回目: 現在の物理行の末尾に移動
  2. 2回目: 論理行の末尾に移動

- **Home / Ctrl+A**:
  1. 1回目: 現在の物理行の先頭に移動
  2. 2回目: 論理行の先頭に移動

#### 2.2.4 表示の更新（MUST）
- 文字の挿入・削除時に即座に再計算・再描画
- 折り返し位置の変化に対応
- 全体の行数増減にも対応

### 2.3 履歴機能

#### 2.3.1 基本動作（MUST）
- **履歴の記録**: Enterキーで確定した入力を履歴に保存
- **履歴の呼び出し**: カーソルキー上下（Ctrl+P/N）で過去の入力を呼び出し
- **履歴の編集**: 呼び出した履歴を編集可能。編集しても元の履歴は変更しない

#### 2.3.2 履歴の保存方式（MUST）
- **デフォルト**: セッション中のみメモリに保持
- **ファイル保存**: パス名を指定された場合
  - 編集開始時にファイルから読み込み
  - 編集完了時（各入力確定後）にファイルへ保存
  - ファイル名はライブラリ利用者が指定
  - 履歴ファイル読み込み時は制御文字を除去

#### 2.3.3 制限（SHOULD）
- **履歴保存数**: 基本無制限だが、設定可能な上限を提供
- **各エントリの最大サイズ**: 入力サイズ制限と同じ
- **履歴ファイル読み込み上限**: 各行が上限を超える場合は無視し、読み込み総量にも上限を設ける

### 2.4 補完機能

#### 2.4.1 補完のトリガー（MUST）
- **プレフィックス文字**: 指定文字（例：`/`, `@`）の入力直後に補完開始
  - 複数のプレフィックスに対応
- **TABキー**: 補完候補の確定専用（トリガーではない）

#### 2.4.2 補完候補の提供（MUST）
- **コールバック関数方式**:
  ```c
  // 現在のテキストとカーソル位置を渡して、候補リストを返してもらう
  char **(*completion_callback)(const char *text, int cursor_pos, int *out_count);
  ```
- **呼び出し頻度**: 文字の入力・削除の度に呼び出し

#### 2.4.3 インクリメンタル絞り込み（MUST）
補完モード中の文字入力で候補を絞り込む：

**例**:
1. `/`を入力 → 候補: `/clear`, `/spark`, `/special`, `/start`
2. `s`を入力 → 候補: `/spark`, `/special`, `/start`
3. `p`を入力 → 候補: `/spark`, `/special`
4. `e`を入力 → 候補: `/special`
5. TABキーで確定 → 入力が`/special`に確定

#### 2.4.4 補完UIの動作（MUST）
- **候補リスト表示**: 入力欄の下側に候補リストを表示
- **候補選択**: カーソルキー上下（Ctrl+N/P）で候補を選択
  - 最初は候補が選択されていない状態
  - ↓を押すと1つ目の候補にカーソルが移動
- **候補確定**: TABキーで選択中の候補を確定
- **補完キャンセル**: Escapeキーで補完モードを終了

#### 2.4.5 その他の動作（MUST）
- **Backspaceでの絞り込み解除**: 文字削除で候補リストが再び広がる
- **候補が0件**: 補完リストを自動的に閉じる。Backspaceで復活可能
- **候補が1つ**: TABキーを押すまで確定しない
- **カーソル移動**: 補完モード中も左右カーソル移動可能
  - カーソル上下のみ候補選択専用

## 3. 非機能要件

### 3.1 文字エンコーディング

#### 3.1.1 対応エンコーディング（MUST）
- **UTF-8**: 必須対応
- **内部表現**: UTF-8バイト列として保持
- **文字幅計算**: terseの`event.data.ch.width`を利用（East Asian Width対応）

#### 3.1.2 対応文字（MUST）
- **ASCII**: 完全対応
- **基本的な日本語**: ひらがな、カタカナ、漢字
- **表示幅**: 半角（1セル）、全角（2セル）、結合文字（0セル）

#### 3.1.3 将来課題（COULD）
- **複雑なグラフィームクラスタ**: 複数コードポイントからなる絵文字（例：👨‍👩‍👧‍👦）
  - 初期バージョンでは「表示可能だが削除時に不完全になる可能性」という制限付き

### 3.2 サイズ制限

#### 3.2.1 基本方針（MUST）
- **デフォルト**: 基本無制限（メモリが許す限り）
- **設定可能**: ライブラリ利用者が上限を設定可能

#### 3.2.2 制限項目（SHOULD）
- **最大入力サイズ**: 初期サイズ小、必要に応じて動的拡張、合理的な上限（例：1MB）
- **上限超過時の挙動**: 入力サイズ上限を超える追加は拒否する
- **最大行数**: 制限なし（設定可能）
- **履歴保存数**: 制限なし（設定可能、推奨デフォルト：100件）

### 3.3 移植性

#### 3.3.1 対応プラットフォーム（MUST）
- **初期ターゲット**: POSIX準拠環境
- **POSIX依存機能**: ソースファイルを分離し、移植性を確保

#### 3.3.2 依存関係（MUST）
- **terse**: 端末制御ライブラリ（必須依存）
  - RAWモード切り替え以外の端末制御をterseが担当
  - terse-promptは編集機能の実装に集中

### 3.4 テスティングフレームワーク

#### 3.4.1 テストツール（MUST）
- **attest**: Google Test風の自作ライブラリを使用

## 4. ユーザーインターフェース設計

### 4.1 API構成

#### 4.1.1 シンプルラッパー（MUST）
1つの関数呼び出しで全機能を使えるお手軽API：
```c
char *terse_prompt(const char *prompt_text);
```

#### 4.1.2 カスタマイズ可能なフレームワーク（MUST）
詳細な制御が可能な低レベルAPI：
- 設定のカスタマイズ
- イベントハンドリング
- 補完・履歴のカスタマイズ

（具体的なAPI設計は別ドキュメント参照）

## 5. 優先順位

### 5.1 MUST（必須機能 - v1.0）
- 基本編集機能（入力、削除、カーソル移動、確定）
- 複数行編集（折り返し表示、物理行/論理行）
- UTF-8対応（基本的な日本語とASCII）
- 履歴機能（メモリ保持、ファイル保存）
- 補完機能（インクリメンタル絞り込み、Claude Code風UI）
- Emacs風キーバインディング

### 5.2 SHOULD（重要だが必須ではない）
- サイズ制限の設定機能
- 履歴保存数の制限

### 5.3 COULD（将来実装を検討）
- 構文ハイライト
- コピー&ペースト（ライブラリ内キルリング）
- Undo/Redo
- 複雑なグラフィームクラスタ対応

---

## 6. 制約事項

### 6.1 技術的制約
- terse APIの制約に従う
- POSIX環境を前提とする（初期バージョン）

### 6.2 初期バージョンの制限
- 複雑な絵文字（グラフィームクラスタ）は表示可能だが編集時に問題が生じる可能性
- OSのクリップボード機能のみ対応（ライブラリ独自のコピペ機能なし）
- 構文ハイライトは未対応
