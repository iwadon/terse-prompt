### 3.2 `test_validation.c` の失敗原因

すべてのテストが `ASSERT_NE(result, NULL)` で失敗しています。これは `tprompt_readline()` が NULL を返していることを意味します。

**失敗しているテスト**:
1. `NoCallback_AcceptsImmediately` - コールバックなしでの即座確定
2. `AlwaysAccept_AcceptsImmediately` - 常にACCEPTを返すコールバック
3. `AlwaysReject_RequiresCtrlEnter` - 常にREJECTを返すコールバック
4. `Continue_InsertsNewlineInMultilineMode` - CONTINUEでの改行挿入
5. `Continue_BeepsInSingleLineMode` - シングルラインモードでのCONTINUE
6. `CallbackInvokedOnConfirmation` - 確定時のコールバック呼び出し
7. `CallbackInvokedMultipleTimesOnReject` - REJECT時の複数回呼び出し

**推定原因**: 検証機能の統合が不完全。おそらく以下のいずれか：
- 検証コールバックの呼び出しロジックに問題
- 検証結果の処理が未実装
- テスト用の疑似入力イベント生成に問題

## 8. パフォーマンス特性

### 8.1 メモリ管理

- **初期バッファサイズ**: 256バイト
- **動的拡張**: 2倍ずつ拡張（最大1MB）
- **履歴デフォルト上限**: 100エントリ
- **メモリリーク**: 未検証（valgrind実行予定）

### 8.2 計算量

| 操作 | 計算量 | 備考 |
|------|--------|------|
| 文字挿入 | O(n) | n = カーソル以降の文字数 |
| 文字削除 | O(n) | n = カーソル以降の文字数 |
| カーソル移動 | O(1) | goal_columnキャッシュ利用 |
| 物理行計算 | O(n) | n = テキスト全体の長さ |
| 履歴追加 | O(1) | 連結リスト先頭追加 |
| 履歴ナビゲーション | O(1) | ポインタ移動のみ |
| 補完候補更新 | O(m) | m = 候補数（アプリ依存） |
